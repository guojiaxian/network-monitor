## 3.1 沙箱预演记录（2026-10-26，真实探针 + 真实中心端）

在测试环境用真实探针（联通1号线绑定探针）预演了可自动化的事件级场景，结果如下。现场验收时仍需按上述清单全量执行（尤其涉及真实线路商、真实邮件、多楼层联动的场景）。

| 场景 | 预演方法 | 触发耗时 | 恢复耗时 | 结果 |
|---|---|---|---|---|
| 1 线路中断（P1） | iptables 阻断探针到全部公网探测目标（网关不动），恢复后解除 | **46 秒**（期间先升级出 P2 降质，符合设计） | **12 秒** | ✅ 通过 |
| 8 静默有效性 | 阻断期间创建静默 → 告警 0 触发（70s 观察）；不解除阻断直接删静默 → 27s 内补触发；解除阻断 → 5s 恢复 | 抑制率 100% | 删静默后 27s（静默缓存 30s 窗口，符合设计） | ✅ 通过 |
| 4 线路降质（P2） | tc netem 对探针出口网卡注入 40% 丢包 150s | 降质事件保持活跃（未产生重复告警——去重逻辑正确） | 迟滞恢复：丢包样本老化出 5 分钟窗口后 02:04:18 自动 RESOLVED | ✅ 通过 |
| 3 监控盲区（P0） | 12 台压测探针进程停止 | 全部在 60s 内产生 P0 盲区告警；探针删除后其告警自动收口（幽灵清理） | — | ✅ 通过 |
| 7 探针自更新 | 见《README 验证记录》：上传 v0.2 → 下发 → 下载校验替换 → 重启上报 | — | — | ✅ 通过 |
| 6 中心端重启 | 见《README 验证记录》：停中心期间探针缓存，恢复补传 | — | — | ✅ 通过 |
| 5 带宽不达标 | 见《README 验证记录》：连续 2 次测速 < 契约 70% 触发 | — | — | ✅ 通过 |

**性能预演（12 探针满配规模）**：30 天历史回填 255 万样本 5 秒写完；VM 磁盘 25MB（90 天估算 <100MB）；总览 API 2~4ms、7 天曲线 3.6ms、周报 35ms；实时流服务端 CPU 17%/内存 0.2%。详见 README 验证记录。

**预演结论**：告警触发/恢复时延、静默抑制、去重、迟滞恢复、盲区检测、自更新闭环全部符合设计预期。剩余需现场执行的：场景 2（真实楼层网关故障）、真实邮件送达验证（场景 1/8/9 的邮件环节）、场景 9 自动日报的到时触发。
