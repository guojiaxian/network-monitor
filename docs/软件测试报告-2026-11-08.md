## 2. 必修复缺陷（已修复并验证）

| # | 缺陷 | 根因 | 修复 | 验证 |
|---|---|---|---|---|
| 1 | 告警阈值可被置 0/负数，导致全站误报或告警失效 | `PUT /settings` 仅钳位 `eval_interval_s`/`type_fail_window_s`；`blind_secs=0` 会让所有探针立即变盲区、`loss_window_min=0` 使降质永不判定 | 服务端对 blind/line_down/loss 阈值/窗口统一钳位回落默认；前端输入加 min/max 并保存前钳位 | API `G3/G4` 断言 0/负数被回落 60/30/10/5；前端 55 项回归 |
| 2 | 探测周期/超时可设 0 或 1 秒，可能造成高频探测 | `agent_config` 未校验 interval/timeout | 服务端统一钳位：ping/tcp/dns/http 5~3600s，timeout 1~10s；前端同步 | `G14/G15` 越界值回落默认 |
| 3 | 并发同名创建楼层/线路可产生重复记录 | 先 `SELECT count` 再 `INSERT`，非原子 | 名称检查+写入放入同一事务，并按名称加 `pg_advisory_xact_lock` 串行化 | 并发同名 10 次：修复前 3 成功 → 修复后 **1 成功 / 9 拒绝** |
| 4 | 更新不存在的楼层/线路 ID 静默返回成功 | `UPDATE` 0 行仍返回原 ID | `ErrNotFound` → handler 404 | `B10/C6b` 均 404 |
| 5 | 楼层 CIDR 非法仍可入库（API 与 CSV 导入） | 仅扫描时校验 | 新增 `normalizeFloorCIDR`：IPv4、/22 及更窄、规范化为网络地址；CSV 同步校验并跳过坏行 | `B9/B9b` 400；CSV 坏 CIDR/坏名称/列数不足均进 `skipped` |
| 6 | 探针改名可写入引号/反斜杠/换行 | `updateProbeMeta` 未校验 | 与楼层/线路同口径 `validDisplayName`；空串允许（回退主机名） | `D19/D20` 400/200 |
| 7 | 线路中断恢复后立刻误报 P2“线路降质” | 5 分钟丢包窗口仍含中断期失败样本，`line_down` 收口后立即评估降质 | `resolveLocked` 记录中断收口时刻；中断进行中或收口后一个丢包窗口内不评估降质（`recentOutageLocked`） | 专项 5/5：恢复后窗口内 0 误报，窗口外正常触发；生产演练线路2/4 复现后已修复 |
| 8 | 麒麟/无 emoji 字体环境 UI 图标显示方框“□” | 侧栏/顶栏/大屏/按钮使用 emoji 作图标 | 全部改为纯文本标签（保留已验证可渲染的 ✓/×） | 生产截图目检：无方框；55 项前端回归 |
| 9 | CSV 导入表头识别依赖“已导入计数”，首行失败会误判后续行 | `n == 0` 判定表头 | 独立 `first` 标记；补齐名称/CIDR/列数校验并给出跳过原因 | 定向 CSV 用例：1 导入 + 3 条明确 skipped |
| 10 | 扫描接口请求体无大小限制 | `json.NewDecoder(r.Body)` | `http.MaxBytesReader(...,64KB)` | 超大 body 返回 400 |

## 3. 关键测试明细

### 3.1 接口/业务逻辑（141 用例）

- 初始化/登录/会话：未初始化/重复初始化、弱密码、错误密码、非法 JSON、30 天会话；
- 楼层/线路：空名/空白/引号/反斜杠/超长、重名、非法 CIDR、过宽 CIDR、空 CIDR、CSV 导入、出口 IP 变化留痕；
- 探针：错误令牌/错误 secret、注册、配置下发、心跳、指标上报（空/坏 JSON/>8MB/未知类型）、绑定/解绑/改名/删除；
- 扫描：空选择、不存在楼层、坏 CIDR、同步 /32、异步多楼层、运行中重复发起 409、记录分页/明细/汇总/时间过滤；
- 历史：非法 type、limit/offset 边界、start/end 反转、31 天钳位、targets 截断、labels 白名单；
- 设置：未知键、坏 JSON、scan/report/internal/industry/syslog/agent/alert 各校验与钳位、SMTP 密码占位符；
- 告警/静默/报表/用户/RBAC：静默时长边界、日报生成、CSV/DOCX 导出、viewer 只读、最后管理员保护、改密/登出；
- 安全：SQL 注入名称按字面量存储、路径穿越被拒（400 `invalid URL path`）、超大 body、越界 id。

## 5. 可选优化（未实施，建议后续排期）

| # | 优化项 | 说明/建议 |
|---|---|---|
| 1 | 指标上报在 VM 写失败时仍返回 200 | 当前仅记日志，VM 宕机期间样本静默丢失；可改为 5xx 让探针走本地缓存补传，或中心侧落盘 spool 后重试 |
| 2 | 楼层/线路名称仅靠 advisory lock 保证唯一 | 可加 `UNIQUE INDEX` 做数据库级约束；升级前需先清理历史重复名，或迁移中自动改名 |
| 3 | 探针注册允许空名称/空主机名，同 IP/名称可重复注册 | 建议至少要求 name 或 hostname 非空；同一 source_ip+name 重复注册时提示/覆盖而非新增 |
| 4 | history 的 `end` 极小值会产生负时间戳桶 | 如 `end=100` 时返回 1970 前桶；可将 start 钳到 ≥0 或 end 钳到合理范围 |
| 5 | `PUT /settings` 为整体替换语义 | 只发部分字段会清空其余字段（文档已注明，前端也总是发全量）；可提供 PATCH/合并语义降低误用 |
| 6 | VM `:8428` 在局域网无认证 | 仅内网且为 vmui 设计；如不需要局域网 vmui，建议改绑 127.0.0.1；否则加反向代理认证/防火墙白名单 |
| 7 | 全站 HTTP 明文、Cookie 无 Secure | 当前为内网 HTTP；如跨网访问，建议 TLS 终止（反代）+ Secure/HttpOnly/SameSite |
| 8 | 登录无防爆破（用户明确要求不做） | 风险已接受；如策略变化，可加 IP+用户名滑动窗口限速 |
| 9 | 中断恢复后的降质抑制采用“整窗口跳过” | 会把手动恢复后真实劣化延迟最多一个窗口（默认 5 分钟）；如需更快，可精确排除中断时段样本而非整窗 |
| 10 | 未纳入 CI 的死代码/格式检查 | 建议加 `gofmt -l`、`go vet`、`staticcheck`/`deadcode` 与前端 lint 到流水线 |
| 11 | `cmd/loadgen`、`cmd/sshmockd` 为测试工具 | 保留有价值；建议在 README/代码地图标注“仅测试环境”，避免误入生产 |
| 12 | Docker Compose 与原生部署端口/描述不完全一致 | docker-compose 仍用 8080；如保留该部署方式，建议在 README 明确“原生 :80 / Docker :8080” |

## 6. 未覆盖/已知限制

- 未做 `-race`（CGO 未启用）；未做长时间 7×24 soak、混沌网络（延迟/抖动/乱序）与浏览器矩阵（仅 headless Chromium）。

- 多探针同线路交叉验证的并发断联未单独演练（生产 12 条线路均为单探针；隔离栈已验证线路级投票逻辑与单测）。
