## 1. 系统组成与依赖

| 组件 | 形态 | 位置 | 端口 |
|---|---|---|---|
| netwatch-server | Go 静态二进制 + systemd | 中心服务器 `/opt/netwatch/bin/` | 8080（默认，Web/API；生产 10.8.14.200 已改 :80） |
| PostgreSQL 12+ | 系统源安装 | 中心服务器 | 5432（仅本机） |
| VictoriaMetrics | 单二进制 + systemd | 中心服务器 `/opt/netwatch/bin/` | 8428（仅本机） |
| netwatch-agent | Go 静态二进制 + systemd | 每楼层探针 VM `/usr/local/bin/` | 无（出站连中心） |
| 前端 | 静态文件 `web/dist` | 中心服务器 `/opt/netwatch/web/dist`，由 server 托管 | — |

数据目录：
- `/opt/netwatch/data/agent-releases/` — 探针版本发布文件（自更新用）
- PostgreSQL — 楼层/线路/探针/告警/静默/报表/用户/审计/设置
- VictoriaMetrics `/opt/netwatch/vmdata/` — 全部时序指标（保留 90 天）

## 2. 中心端部署（一键脚本，全新麒麟 V10）

**前置**：交付包 `netwatch-0.2.tar.gz` 已自包含全部二进制（netwatch-server/agent、VictoriaMetrics、前端），**现场零下载**；解压到任意目录后执行即可。

```bash
tar xzf netwatch-0.2.tar.gz && cd netwatch-0.2/deploy
CHECK_ONLY=1 ./install-server.sh     # （可选）只跑环境检查预览
./install-server.sh                  # 一键部署，脚本可重复执行（幂等）
```

脚本自动完成（约 5 分钟）：
1. **环境检查**：root/架构/系统（麒麟及 RHEL 系）/内存/磁盘/端口 8080·5432·8428 占用/二进制完整性，任何一项不满足即中止并说明；
2. **chrony 时间同步**启用；
3. **防火墙**自动放行 8080（firewalld 运行时）；SELinux Enforcing 时给出处置提示；
4. **PostgreSQL** 自动 yum 安装 → initdb → 启动 → 创建库与随机口令用户 → pg_hba 放行本机密码认证（口令写入 `/opt/netwatch/.pg-pass`）；
5. **VictoriaMetrics**（包内自带二进制）安装启动；
6. **中心服务**安装启动，数据库口令自动生成写入 systemd 单元，注册令牌自动随机生成；
7. **部署自验证**：三项健康检查全过才算成功。

完成后浏览器打开 `http://<本机IP>:8080` → 初始化向导。重跑脚本即升级（数据保留）。SELinux Enforcing 且启动失败时的处置见脚本输出提示。

> **生产环境（10.8.14.200，2026-11-05 部署）**：监听端口改为 **80**（unit 内 `NW_LISTEN=:80`，firewalld 放行 80/tcp），探针接入地址相应为 `http://10.8.14.200`；部署后手工保存了注册令牌副本 `/opt/netwatch/.enroll-token`（0600）。本文其余 `8080` 均为脚本默认值。

## 2.1 Docker Compose（备选）

若倾向容器化：`cd deploy && docker compose up -d`（一键起 VictoriaMetrics + PostgreSQL + server，数据卷持久化）。数据库口令与注册令牌在 `docker-compose.yml` 中修改。

## 3. 探针部署（每楼层 1 台，12 台批量）

> **完整流程已独立成册：《08-探针部署与配置手册》**——含探针工作原理、部署前准备、单台/批量安装、绑定与分组、SSH 运维凭据、探测参数与测速配置、外网组部署、版本升级、逐台验证清单与故障排查。本节仅留速查。

```bash
# 单台（探针 VM root 执行；第 4 参数为探针名称，克隆模板必传）
./install-agent.sh http://<中心IP>[:端口] <注册令牌> "" "2楼-东配线间"
# 批量 12 台（操作机免密 SSH；CSV 每行：IP,SSH用户,名称[,端口]）
./batch-install-probes.sh probes.csv http://<中心IP>[:端口] <注册令牌>
```

装完后到管理后台「探针管理」**绑定线路与分组（先绑定再启用）**，再到「探针状态」页确认全部 online（只读、15 秒自动刷新）。探测参数由中心统一下发（系统设置 → 探测配置），装完机无需登录探针。

## 4. 升级

**中心端升级**：
```bash
# 新二进制放置后原子替换并重启，秒级完成（探针会自动缓存补传期间数据）
install -m 0755 netwatch-server /opt/netwatch/bin/netwatch-server.new
mv /opt/netwatch/bin/netwatch-server.new /opt/netwatch/bin/netwatch-server
systemctl restart netwatch-server
# 回滚：替换回旧二进制 + restart 即可
```

**探针升级（推荐走后台）**：探针管理页 → "版本发布与升级"卡上传新版本（版本号+二进制，中心记 SHA256）→ 选好目标版本 → 展开各探针"⚙ 运维"点「升级到 ×.×」。探针自动下载、SHA256 校验、原子替换、重启，失败不影响原版本。灰度建议：先升 1 台观察 10 分钟再全量（详见《08》§5.7）。

**数据库结构变更**：由中心端启动时自动执行（`CREATE TABLE IF NOT EXISTS` / `ALTER ... IF NOT EXISTS`），升级中心端即完成。

## 5. 日常巡检与备份

> 数据库结构详解、指标体系、常用 SQL 配方与恢复演练见《09-数据库结构与运维手册》；本节为速查。

每日巡检（或接入现有巡检平台）：
```bash
curl -s http://127.0.0.1:8080/healthz                                   # 中心存活
curl -s http://127.0.0.1:8428/health                                    # 时序库存活
systemctl is-active netwatch-server victoriametrics postgresql          # 服务状态
df -h /opt/netwatch                                                     # 磁盘（VM 90 天约 <10GB）
```

备份（建议 crontab 每日 02:00）：
```bash
# 业务库（含配置、告警历史、报表）
su postgres -c "pg_dump netwatch | gzip > /backup/netwatch-pg-$(date +%F).sql.gz"
# 时序库：停写快照或直接备份目录（VM 支持 snapshot API）
curl -s 'http://127.0.0.1:8428/internal/snapshot/create'    # 生成快照后拷贝快照目录
# 探针版本目录与 systemd 单元一并备份
tar czf /backup/netwatch-data-$(date +%F).tgz /opt/netwatch/data /etc/systemd/system/netwatch-*.service
# 保留 14 天
find /backup -name 'netwatch-*' -mtime +14 -delete
```

恢复：新建空库 → `gunzip -c xxx.sql.gz | su postgres -c "psql netwatch"` → 恢复 vmdata 快照目录 → 启动服务。时序数据丢失不影响配置与告警历史，仅影响历史曲线。

## 6. 常见故障处置

| 现象 | 判断 | 处置 |
|---|---|---|
| P1 线路中断告警（网关正常） | 宽带线路/出口故障 | 先看总览确认全部公网目标失败；拨打线路商报障（附告警邮件中的时间与现象）；恢复后系统自动发恢复邮件 |
| P1 楼层中断告警（网关不通） | 楼内接入/网关故障 | 检查楼层交换机、网关设备供电与上联口；与线路无关，勿报线路商 |
| P0 监控盲区（探针失联） | 探针 VM 宕机或与中心失联 | 检查该探针 VM 运行状态与网络；若计划维护请先在"系统设置 → 告警策略"建静默窗口 |
| P2 降质/带宽不达标 | 线路质量/带宽劣化 | 连续观察 2 个统计窗口；结合测速曲线（线路详情页）判断是否报障；高峰期可调整测速时段 |
| P2 内网服务不可达（monitor_down） | 中心服务器探测内网服务（OA/交换机等）连续 3 次失败 | 检查该内网服务本身是否存活、端口是否变更；若为计划内停机请先到"系统设置 → 告警策略"建静默窗口或删除该监控目标 |
| 探针不出现在后台 | 注册令牌不符/网络不通 | 核对令牌（系统设置 → 探测配置）、`curl http://<中心>:8080/healthz` 连通性、`journalctl -u netwatch-agent` |
| 邮件收不到 | SMTP 配置/网络 | 系统设置 → 通知渠道 → 测试邮件；查 `journalctl -u netwatch-server | grep "send mail"`；确认单位邮件网关未拦截 |
| 中心端起不来 | DB 连接失败 | `journalctl -u netwatch-server`；核对 NW_DB 口令与 pg_hba 配置；`pg_isready` |
| 大屏打不开 | 静态文件缺失 | 确认 `/opt/netwatch/web/dist/index.html` 存在（重新 `make web` 并同步） |
| 时序库磁盘增长过快 | 保留期配置 | 默认 90 天；可调 `-retentionPeriod`，重启 victoriametrics 生效 |

## 7. 安全基线与前置要求

- **全部探针 VM 与中心服务器必须配置 NTP 时间同步**：探测样本时间戳由探针产生，时钟偏差会造成判定窗口失真与曲线错位（服务器已内置防护：样本时间快于服务器 >2 分钟会钳位到服务器时间并记日志 `clock skew`，发现该日志请校时）。
- **钉钉/企业微信群机器人**：钉钉自定义机器人若开启"关键词过滤"，请把关键词设为 `NetWatch`（推送消息标题均含该词），或改用加签模式（系统设置填 SEC 密钥）。
- **SSH 运维凭据**：探针 root 密码导入后以 AES-256-GCM 加密存储，主密钥在 `/opt/netwatch/data/ssh-master.key`（0600）——**备份时一并保存，泄露即重置探针密码**。远程命令功能仅管理员可用且全部进入审计日志；建议为探针创建专用运维账号而非直接用 root，密码定期轮换（后台改密即可）。
- 管理口令强口令；观察者账号发值班人员；人员变动及时在"系统设置 → 用户与审计"删除。
- 注册令牌定期更换（系统设置 → 探测配置 → 注册令牌；旧探针凭证不失效，新增探针用新令牌）。
- 中心端 8080 仅对内网开放；PostgreSQL/VictoriaMetrics 端口仅本机监听（默认配置已满足）。
- 大屏地址为公开只读，不含管理功能；如需限制可由防火墙限定访问源。

## 8. 管理员账号与密码重置

- **系统没有默认账号密码**：首次访问自动进入初始化向导，由部署者自行创建管理员（这是刻意设计，避免出厂弱口令）。
- **忘记密码**：由另一位管理员在"系统设置 → 用户与审计"重建账号；仅剩唯一管理员时，在数据库清空用户表后重新走向导（**只影响登录账号，监控数据/配置/告警历史全部保留**）：

```bash
# PostgreSQL 原生部署：
su postgres -c "psql netwatch -c 'DELETE FROM users;'"
# Docker 跑 PG：
docker exec netwatch-pg psql -U netwatch -c 'DELETE FROM users;'
# 然后刷新管理页面 → 自动进入初始化向导 → 重新创建管理员
```

- 观察者账号由管理员在「系统设置 → 用户与审计」增删，无需数据库操作。
