# NetWatch 数据库表说明

> 生产：PostgreSQL 10.5（`/var/lib/pgsql/data`，仅本机 5432，hba 密码认证）+ VictoriaMetrics v1.102.1（`:8428` 监听全网卡供局域网 vmui，无认证勿映射外网；保留 2 年）
> 本文核对自 `internal/server/store.go` / `tsdb.go` 及生产实测（全库 8.4MB）。巡检/备份/SQL 配方等运维操作见 `AGENTS.md` §8/§14。

---

## 1. 双库分工

| 存储 | 存什么 | 特点 |
|---|---|---|
| **PostgreSQL**（库 `netwatch`，11 张表） | 业务事实：楼层/线路/探针/告警/静默/报表/用户/审计/设置/版本发布/IP 扫描记录 | 全部配置的**唯一权威来源**，重启不丢 |
| **VictoriaMetrics** | 时序样本：全部探测曲线 | 只追加，**2 年自动过期**；丢失只影响历史曲线 |

库外状态：Web 会话**持久化在 PG `sessions` 表**（Cookie 30 天，server 重启不踢登录；内存只做一级缓存）；SSH 凭据密文在 PG 但**主密钥在 `data/ssh-master.key`**；探针本地 `identity.json`（身份）+ `cache.jsonl`（断网缓存 48MB 上限、500 条/批补传）。**IP 扫描任务本体是内存态**（见 3.7）。

## 2. 表关系

```
floors ──< lines ──< probes
             │  ＼
             │   └──< silences      （删线路 → 级联删静默）
             └─ 弱关联：alerts.line_id / alerts.probe_id（普通列，无外键）
独立表：settings / users / audit / reports / agent_releases / scan_runs
```

外键行为：删楼层 → 线路 `floor_id` 置 NULL；删线路 → 探针解绑（SET NULL）+ 静默级联删除；删探针（后台）→ 其盲区告警与幽灵状态自动收口。

## 3. 各表结构

### 3.1 floors（楼层/子网）

| 列 | 类型 | 说明 |
|---|---|---|
| id | SERIAL PK | |
| name | TEXT | 楼层名（如"3楼"） |
| cidr | TEXT | 子网 CIDR |
| gateway | TEXT | 核心/共同网关（核心交换机 SVI，如 10.8.32.253）；空=不监测。wifi 两段、104 两段可填同一地址，中心按 IP 去重探测 |
| created_at | TIMESTAMPTZ | |

### 3.2 lines（宽带线路）

| 列 | 类型 | 说明 |
|---|---|---|
| id | SERIAL PK | 被 probes/silences 引用 |
| name | TEXT | 线路名（唯一性由后台校验） |
| isp | TEXT | 运营商（默认'联通'；可由探针自动探测回填） |
| public_ip | TEXT | 出口公网 IP（**由探针每 5 分钟探测对账纠偏**，手工改写约 15s 被纠正） |
| contract_down_mbps / contract_up_mbps | INT | 契约带宽 = 带宽不达标告警阈值；0=不判 |
| floor_id | INT → floors | ON DELETE SET NULL |

### 3.3 probes（探针）

| 列 | 类型 | 说明 |
|---|---|---|
| id | **TEXT** PK | 探针 ID（注册生成，探针本地持久化复用） |
| secret | TEXT | 上报凭证（每次上报鉴权） |
| hostname / os / arch / version / source_ip / gateway | TEXT | 注册与心跳自报（含资产信息） |
| name | TEXT | 后台设置的显示名 |
| line_id | INT → lines | 绑定线路 |
| ssh_host / ssh_port / ssh_user / ssh_pass_enc | | 零接触运维凭据；密码仅存 **AES-256-GCM 密文** |
| pending_version | TEXT | 待升级版本号（完成自动清空） |
| enrolled_at / last_seen | TIMESTAMPTZ | 注册时间 / 最后心跳（盲区判定：>60s） |

### 3.4 alerts（告警，唯一带索引的大表）

| 列 | 类型 | 说明 |
|---|---|---|
| id | BIGSERIAL PK | |
| fingerprint | TEXT | 同一问题唯一指纹（状态翻转依据） |
| severity / kind | TEXT | P0/P1/P2；kind=blind/line_down/floor_down/floor_gw_down/floor_anchor_down/degraded/speed_low/probe_conflict/monitor_down/probe_resource/industry_down/probe_type_fail |
| title / body | TEXT | 标题与详情（邮件正文同源） |
| probe_id / line_id | TEXT / INT | 弱关联（无外键） |
| starts_at / ends_at | TIMESTAMPTZ | 触发/恢复时间 |
| status | TEXT | `firing` / `resolved` |

恢复 = 更新原行（status→resolved、补 ends_at），不新增行。索引 `idx_alerts_status(status, starts_at DESC)`。**无自动清理**。

### 3.5 settings（全部可配置项，JSONB）

| key | 内容 | 后台入口 |
|---|---|---|
| agent_config | 探测下发（间隔/超时/目标 + **version 乐观锁**，手改不递增则不下发） | 设置 → 探测配置 |
| internal_monitors | 内→内内置监控 | 设置 → 探测配置 |
| industry_monitors | 行业网监测（仅 ICMP ping） | 设置 → 探测配置 |
| floor_net_monitors | 楼层网关/汇聚设备监测：`enabled` / `interval_s`（默认 10）/ `timeout_s`（默认 1）/ `fail_n`（默认 3）/ `anchors[{name,target,floors,type}]`；网关在 `floors.gateway`，锚点在此；相同 IP 只探测一次 | 设置 → 探测配置 → 楼层网关与汇聚设备 |
| scan_settings | IP 扫描定时计划：`enabled` / `interval_min`（5~1440，默认 60）/ `floor_ids`（空=全部有 CIDR 的楼层） | 设置 → 探测配置 → IP 扫描计划 |
| smtp | 邮件服务器（GET 时密码掩码 `__SET__`，PUT 空/占位符=保留原值） | 设置 → 通知渠道 |
| notify_channels | 钉钉/企微 webhook | 设置 → 通知渠道 |
| syslog_settings | 日志外发（syslog → 日志审计服务器）：`enabled` / `host` / `port`（默认 514）/ `proto`（udp|tcp）/ `format`（cef|kv）/ `app_name` / `send_alerts` / `send_speed` / `send_scan` / `send_egress` | 设置 → 通知渠道 |
| alert_settings | 告警阈值 + 收件组 | 设置 → 告警策略 |
| speed_settings | 测速引擎/间隔/下载源 | 设置 → 采集与测速 |
| snmp_settings | SNMP 采集 + 接口映射 | 设置 → 采集与测速 |
| report_settings | 日报/周报计划 | 设置 → 报表推送 |
| agent.enroll_token | 注册令牌（**存在即覆盖** unit 环境变量） | 设置 → 探测配置 |

首次启动自动写入 9 个默认键（`ON CONFLICT DO NOTHING`）；API PUT 有白名单（仅以上 11 键）。

### 3.6 其余表

| 表 | 用途 | 要点 |
|---|---|---|
| users | 后台账号 | username UNIQUE；bcrypt 密码；role=`admin`/`viewer`（viewer 写操作 403） |
| sessions | 登录会话 | token PK；`exp` 30 天；logout 与过期清理双删（见 `CleanExpiredSessions`） |
| reports | 日报/周报 | kind=day/week；**data JSONB** 存整份统计；CSV 导出由其生成 |
| silences | 静默窗口 | line_id NULL=全部线路；到期自然失效 |
| audit | 操作审计 | 每个写操作一行；后台显示最近 100 条；无自动清理 |
| agent_releases | 探针版本发布 | 元数据（version/sha256/size…）；文件本体在 `data/agent-releases/<版本>/` |
| scan_runs | 楼层 IP 扫描记录 | 每次多楼层扫描一行，见 3.7；**自动清理 7 天前记录并保留最多 3000 行** |
| line_ip_history | 线路出口 IP 变化留痕 | 探针出口对账自动回写与后台手工修改均入轨迹，见 3.8；随线路级联删除 |

### 3.8 line_ip_history（线路出口 IP 变化留痕）

| 列 | 类型 | 说明 |
|---|---|---|
| id | BIGSERIAL PK | |
| line_id | INT | 所属线路（外键，**随线路删除级联清理**） |
| old_ip / new_ip | TEXT | 变化前 / 变化后出口 IP；`old_ip` 为空 = 首次登记（线路身份登记起点） |
| probe_id / probe_name | TEXT | 触发探针（egress 来源=探针 ID/显示名）；手工修改时为空/操作账号 |
| source | TEXT | `egress`（探针心跳出口对账自动回写）/ `manual`（后台手工修改出口 IP） |
| created_at | TIMESTAMPTZ | 变化时间 |

- 索引 `idx_line_ip_history_line(line_id, created_at DESC)`；查询接口 `GET /api/admin/lines/{id}/ip-history`（线路详情页「出口 IP 变化记录」卡）。
- 写入时机（2026-11-07 动态 IP 决议）：绑定探针出口 IP 无匹配线路 → 自动回写绑定线路 `lines.public_ip/isp/geo` 并留痕；命中其他线路身份 → 改绑（不写本表）；线路出口首次登记 → 留痕（old_ip 为空）；后台手工改出口 IP → 留痕（source=manual）。

### 3.7 scan_runs（楼层 IP 扫描记录，一网段一行）

| 列 | 类型 | 说明 |
|---|---|---|
| id | BIGSERIAL PK | |
| batch | TEXT | 批次号（`20261106-170438-d57969`）；同一次手动/定时任务创建的 N 条记录共用，前端用它归组显示进度 |
| floor_id | INT | 楼层（**弱关联**：删楼层后历史保留，前端显示"楼层已删除"） |
| floor_name / cidr | TEXT | 扫描时的楼层名与网段快照（楼层改名/改网段不影响历史） |
| status | TEXT | `pending`（排队）/ `running` / `done` / `error`（网段非法等）/ `interrupted`（中心重启或超 15 分钟无进展） |
| up / down / total | INT | 在线数 / 离线数 / 扫描地址数 |
| duration_ms | BIGINT | 该网段扫描耗时 |
| results | JSONB | 逐 IP 明细 `[{ip,online,rtt_ms}]`，扫完即写（中断也保留已完成网段） |
| trigger | TEXT | `manual`（后台"开始扫描"）/ `schedule`（探测配置里的定时计划） |
| created_by / created_at | TEXT / TIMESTAMPTZ | 发起人（定时任务=`system`）/ 发起时间 |

- 索引 `idx_scan_runs_created(created_at DESC)`、`idx_scan_runs_floor(floor_id, created_at DESC)`。
- **保留策略**：每次建新批次时清理——删 7 天以前的、再按 3000 行硬上限截断（明细 JSONB 较大；60 分钟间隔全量扫约 336 行/天，7 天约 2.4 千行/35MB）。
- 执行器 `internal/server/scansched.go` 的 `ScanRunner`：手动与定时共用一把闸（**同一时刻只跑一批**，全局 64 并发不叠加）；逐网段串行，每网段一行。
- 定时计划存 `settings.scan_settings`（`enabled` / `interval_min` / `floor_ids`），每 30s 重读；是否到点按"最近一次 `trigger='schedule'` 记录时间 + 间隔"判断（落库，重启不重复扫）。
- **线路在线 IP 数**（线路状态/线路详情）即取本表：每楼层最近一条 `status='done'` 记录求和，SQL 为 `DISTINCT ON (floor_id) ... ORDER BY floor_id, created_at DESC`。
- 记录列表接口不返回 `results`（避免一次拉几十万行），点开记录行才按需 `GET /api/admin/scan/runs/{id}` 取明细。

## 4. VictoriaMetrics 指标体系

| 指标 | 含义 | 标签 |
|---|---|---|
| nw_ping_rtt_ms / nw_ping_ok / nw_ping_loss_pct | ICMP 时延/成败/丢包 | probe, line, class=`gw`\|`public`, target |
| nw_floor_net_ok / nw_floor_net_rtt_ms | 中心自探楼层网关/汇聚设备成败/时延（探测历史 type=floornet） | class=`gateway`\|`anchor`, kind=`gateway`\|`switch`\|`ac`\|`aggregation`, floor, name, target（人类可读目标） |
| nw_tcp_rtt_ms / nw_tcp_ok | TCP 连通 | probe, line, target |
| nw_dns_rtt_ms / nw_dns_ok | DNS 解析 | probe, line, target |
| nw_http_ttfb_ms / nw_http_ok / nw_http_code / nw_http_cert_days | HTTP 首字节/成败/状态码/证书剩余天数 | probe, line, target |
| nw_speed_down_mbps / nw_speed_up_mbps | 测速上下行 | probe, line, target |
| nw_snmp_in_bps / nw_snmp_out_bps | 防火墙 WAN 口真实流量 | line（中心采集） |
| nw_monitor_ok / nw_monitor_rtt_ms | 内→内内置监控 | monitor, type（无 probe 标签） |

- `class=gw|public` 区分网关/公网探测，是楼层中断/线路中断分类判定与探测历史分类的基础；
- 保留 2 年；量级参考：12 线路满配 30 天 <100MB；
- **即时查询有 ~30s latencyOffset**（刚写入查不到属正常；导出/区间查询不受影响）；
- 原生 API 监听 `:8428`（本机/局域网 vmui，无认证，勿映射外网），后台"线路详情/探测历史"已封装常用查询。

## 5. 数据增长与保留

| 数据 | 自动清理 | 建议 |
|---|---|---|
| VM 时序 | ✅ 2 年 | 无需管理 |
| alerts / audit / reports / silences / agent_releases | ❌ | MB 级年增长；需要时按 AGENTS.md §14 配方清理（`DELETE FROM alerts` 等） |
| scan_runs | ✅ 7 天 + 最多 3000 行 | 建批次时自动清理，无需管理 |

表结构变更由**中心端启动时自动迁移**（`CREATE TABLE IF NOT EXISTS` + `ALTER ... ADD COLUMN IF NOT EXISTS`），升级即完成，无需手工 SQL。
