## 3. 发现并修复的缺陷（6 项，均已回归）

| # | 严重度 | 缺陷 | 根因 | 修复 | 回归证据 |
|---|---|---|---|---|---|
| 1 | 中 | 探针刚启动 ~100s 时出现 5s 即恢复的瞬态 P2 降质误报（23:19:08 实测） | `lossStats` 每目标 ≥10 样本的门槛是"各自独立成立"的：启动期各目标样本数因抖动不同步，坏目标（114.114.114.114 对本线路 ICMP 100% 不通）先凑满时，"下中位数"退化为该目标自身 100% | 门槛改为**全部目标同时成立**（`ratios 数 == 目标数` 才判定） | 新增回归用例 `TestLossStatsAsymmetricSampleCounts`；修复后重启/演练无瞬态误报 |
| 2 | 中 | P1 线路/楼层中断确认后，P2 降质仍叠加触发（23:22:13 降质 + 23:22:33 中断并存），与代码注释"线路中断时不叠加"不符 | 线路判定改为线路级投票时，降质块未接入中断抑制 | 新增 `outageActiveLocked`：中断确认后降质**不触发**，已触发的**并入中断事件**（带恢复原因） | 中断+40% 丢包并存 95s 零降质告警；00:06 演练中已触发的降质在中断确认后被吸收 |

## 4. 观察项（非缺陷，知悉即可）

1. **114.114.114.114 对本线路 ICMP 100% 不通**（真实环境数据）：多目标投票设计正确消化了该坏目标，不影响判定；如需更准的丢包统计，可在后台把 ICMP 目标换成对该线路可 ping 的地址。
2. **Ookla 测速节点差异大**：昆山节点仅 0.3~1 Mbps，同线路 HTTP 实测 24.7 Mbps——测速绝对值仅供参考，建议以 HTTP 引擎交叉验证或更换测速节点池。
3. **dldir1.qq.com 在探针上优先解析为 IPv6**（无 IPv6 出口时首连挂起直至超时）：agent 测速引擎会依次换源重试，无碍；纯 IPv4 内网环境如遇单源挂起可补 IPv4 直连地址。
4. **单探针线路停止探针时，line_down（约 45s）先于 blind（60s）触发**：设计使然——探针经线路汇报，"静默+最后网关正常"对单探针线路就是"疑似断线"，二者随后一起收口；多探针线路中则表现为 P2 探针数据冲突（指向故障探针）。
5. **线路 CSV 导入**：非标准表头（如"名称,ISP,…"）会被当作数据行静默导入。标准表头（首列"楼层名"）可正确跳过；建议现场导入时使用文档 06 §3 的标准格式。
6. **server 会话存内存**：重启后需重新登录（设计如此，已在文档记载）。

## 5a. 补充功能：线路出口公网 IP 自动探测（2026-11-06 凌晨追加）

用户决议变更：线路出口公网 IP **不再手工填写**，由探针自动探测。已实现并验证：

- **探测**：探针启动立即 + 每 5 分钟访问 IP 回显服务（四源依次尝试：`ip.3322.net` / `members.3322.org/dyndns/getip` / `v4.ident.me` / `myip.ipip.net`，已在本线路实测可达性后选型；`4.ipw.cn` 不可达弃用）。
- **上报与回填**：结果随心跳上报（协议新增 `Heartbeat.PublicIP`、`ProbeConfig.IPEchoURLs`，只增字段新旧兼容）；绑定线路时中心自动回填 `lines.public_ip`，并与库**对账纠偏**——手工改写的值在下一轮心跳（≤15s）被探测值覆盖，仅当全部回显服务不可达时手工值作兜底显示。
- **实测证据**（journal）：`00:56:12 egress public ip: 218.28.242.106 (via ip.3322.net)` → `00:56:27 出口公网 IP 自动探测: → 218.28.242.106` → 手工写假 IP 后 `00:57:54 出口公网 IP 自动探测: 9.9.9.9 → 218.28.242.106`。本线路出口实探为 **218.28.242.106（河南联通）**。
- **质量护栏**：IPv4 提取带边界（`999.1.1.1` 不会被误析为 `99.1.1.1`，回归用例 `TestParseIPv4` 覆盖四源真实响应格式）；稳态（库值=探测值）零额外写库。
- 前端线路表单已加"留空=探针自动探测"提示（随并行的前端信息架构重排一并发布）。

## 5b. 补充功能：探针自动检测能力全量落地（2026-11-06 追加）

用户决议："探针还能自动检测出什么？都利用上"。已全部落地并验证：

| 检测项 | 方式 | 验证结果 |
|---|---|---|
| 资产信息（CPU 型号/核数、内存/磁盘容量、内核、发行版、虚拟化、网卡/MAC/MTU） | 注册时采集 + **心跳补报**（不重注册也能刷新/补全），入 `probes.sysinfo` | Hygon C86 7151 / 1C / 893MB / 16GB / KVM / Kylin V10 / 4.19 内核 全部入库 |
| 出口 IP 归属运营商 + 归属地 | ipip 全文解析（"来自于：中国 河南 郑州 联通"），随心跳回填 `lines.isp/geo`（对账纠偏，空值不覆盖） | 自动回填 `联通` / `中国 河南 郑州` |
| 出口 IPv6 | 本机全局 v6 地址预判（零网络依赖）→ 有才探测 v6-only 回显 | 纯 v4 线路正确显示"不支持" |
| 探针自健康（CPU%/内存%/磁盘%） | /proc/stat 差分 + meminfo + statfs，随心跳上报 | cpu 89%/mem 66%/disk 19% 实时展示 |
| **P2 探针资源紧张告警** | 内存或磁盘 >90% 连续 3 次心跳触发，<80% 恢复 | 内存压测（750MB/936MB）80s 触发、释放后自动恢复 ✅ |
| 探针时钟偏移 | 心跳带 AgentTS，服务器算 offset；状态页 >30s 标黄提示配 NTP | offset 0.0s（已对时） |

**证伪项（不实现，防重复踩坑）**：
- **DNS 出口 IP 检测**——公共递归解析器（223.5.5.5 等）对 whoami.akamai.net 返回的是**递归服务自身的出口**（实测 123.6.27.94 ≠ 本线路 218.28.242.106），无法反映本线路 DNS 出口；myip.opendns.com 方案依赖国外解析器，内网环境不可靠。
- DNS 解析结果一致性检测——CDN 按解析器位置返回不同答案属正常行为，一致性≠劫持，误报率高，不做。

**实现要点/踩坑**：
- 资产采集不能只放注册时——身份持久化修复后探针不再重注册，旧探针永远补不上资产；改为周期采集随心跳上报。
- IPv6 探测不能直接信回显端点：api64 双栈端点无 v6 时返回 v4 地址、api6 在污染网络返回 A 记录——都造成"v6=v4 地址"误报；必须先查本机全局 v6 地址 + 校验返回值非 v4。
- 引擎侧空值语义要分清：公网 IP/ISP/归属地有"手工兜底"语义（空=未探得，保留旧值/手工值）；IPv6 无此语义（空=明确无），必须无条件赋值，否则探针降级后旧值永久残留（实测踩坑）。
- 线路手工更新（POST /lines）对自动探测字段（isp/public_ip/geo）空值不覆盖，避免管理员改契约带宽时误清空自动回填的出口信息。
