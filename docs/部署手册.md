# NetWatch 部署手册（中心端 + 探针）

> 适用：银河麒麟 V10 / RHEL 系；生产基线：中心 10.8.14.200:80 + 探针 10.8.14.201（2026-11-05/06 实测通过）
> 配套：《数据库表说明》；告警处置、巡检备份、演练验收等运维知识见 `AGENTS.md`（AI 记忆）§8/§14

---

## 1. 系统组成与依赖

| 组件 | 形态 | 位置 | 端口 |
|---|---|---|---|
| netwatch-server | Go 静态二进制 + systemd | 中心 `/opt/netwatch/bin/` | 8080（脚本默认；生产已改 **:80**） |
| PostgreSQL 10+ | 系统源安装 | 中心 | 5432（仅本机） |
| VictoriaMetrics | 单二进制 + systemd | 中心 `/opt/netwatch/bin/` | 8428（仅本机） |
| netwatch-agent | Go 静态二进制 + systemd | 每楼层探针 VM `/usr/local/bin/` | 无（出站连中心） |
| 前端 | 静态文件 | 中心 `/opt/netwatch/web/dist`，由 server 托管 | — |

数据目录：`/opt/netwatch/data/`（探针版本发布文件、`ssh-master.key`）、PG（全部业务数据）、`/opt/netwatch/vmdata/`（时序，保留 90 天）。

## 2. 中心端部署与启动（一键脚本）

**前置**：交付包自包含全部二进制（server/agent、VictoriaMetrics、前端），现场零下载。

```bash
tar xzf netwatch-0.2.tar.gz && cd netwatch-0.2/deploy
CHECK_ONLY=1 ./install-server.sh     # （可选）只跑环境检查预览
./install-server.sh                  # 一键部署，幂等可重复执行
```

脚本自动完成（约 5 分钟）：环境检查（root/架构/系统/内存/磁盘/端口占用/二进制完整性）→ chrony 对时 → 防火墙放行 + SELinux 提示 → PostgreSQL 自动安装建库（随机口令写入 `/opt/netwatch/.pg-pass`）→ VictoriaMetrics 安装启动 → 中心服务注册启动（随机注册令牌写入 unit）→ 三项健康自验证。

完成后浏览器打开 `http://<本机IP>:8080` → **初始化向导**（建管理员 → SMTP → 线路 CSV，后两步可跳过后补）。重跑脚本即升级（数据保留）。

> **生产（10.8.14.200）差异**：监听 **:80**（unit `NW_LISTEN=:80`，firewalld 放行 80/tcp），探针接入地址 `http://10.8.14.200`；令牌副本 `/opt/netwatch/.enroll-token`（0600）。

### 2.1 日常启停与升级

```bash
systemctl start|stop|restart|status netwatch-server   # 日常启停；日志 journalctl -u netwatch-server -f
# 中心端升级：新二进制原子替换 + 重启（秒级，探针自动缓存补传，回滚=换回旧二进制+restart）
install -m 0755 netwatch-server /opt/netwatch/bin/netwatch-server.new
mv /opt/netwatch/bin/netwatch-server.new /opt/netwatch/bin/netwatch-server && systemctl restart netwatch-server
# 仅改前端：替换 /opt/netwatch/web/dist 即可，无需重启（静态文件按请求从磁盘读）
# 数据库结构变更：中心端启动时自动迁移，无需手工操作
```

### 2.2 Docker Compose 备选

`cd deploy && docker compose up -d`（一键起 VM + PG + server，数据卷持久化；口令与令牌在 `docker-compose.yml` 修改）。

## 3. 探针部署

### 3.1 原理速览

单二进制 + systemd，**无入站端口**；探测结果批量上报中心，配置每 30s 反向拉取（改配置约 30~60s 生效）。首次注册获探针 ID 持久化到 `/var/lib/netwatch-agent/identity.json`，**重启复用身份**（名称/绑定/SSH 凭据保留）。**内网组**（默认）绑线路测网关+公网+测速；**外网组**（阿里云等）探测官网。未绑定内网组探针不产生线路数据并在总览提示。资源要求 1C/1G/磁盘<1G。**必须 NTP 对时**（快于中心 >2min 样本被钳位并记 `clock skew`）。

### 3.2 部署前准备

1. 中心可达：`curl http://10.8.14.200/healthz` 返回 ok；
2. 注册令牌（优先级：settings 键 `agent.enroll_token` **存在则覆盖** unit 环境变量）：生产查看 `grep NW_ENROLL_TOKEN /etc/systemd/system/netwatch-server.service` 或 `cat /opt/netwatch/.enroll-token`；后台"系统设置 → 探测配置 → 注册令牌"字段为空属正常，填入保存即落库生效；
3. 线路与楼层先建好（后台"线路配置"页手工或 CSV 导入，首列表头为"楼层名"）；
4. 探针二进制：交付包 `deploy/netwatch-agent` 或 `make build` 产物 `bin/netwatch-agent`。

### 3.3 单台安装（install-agent.sh，幂等可重跑）

```bash
./install-agent.sh <中心地址> <注册令牌> [探针二进制] [探针名称]
# 生产示例：./install-agent.sh http://10.8.14.200 <令牌> "" "2楼-东配线间"
```

第 4 参数为探针名称（注册后后台直接显示，并自动设 VM 主机名——名称含非 ASCII 时取 ASCII 安全形式、纯数字开头自动加 `probe-` 前缀，如「探针-201」→ `probe-201`；**克隆模板必传**）。脚本六步：基础检查 → 中心连通性 → 与中心对时（偏差 >30s 自动配 chrony）→ 安装 `/usr/local/bin/netwatch-agent` + systemd 服务（CAP_NET_RAW、开机自启）→ **注册确认**（`registered as agent <id>`）→ 状态输出。

```bash
systemctl status netwatch-agent          # 日常状态
journalctl -u netwatch-agent -f          # 日志
# 改中心地址/令牌/名称：编辑 /etc/systemd/system/netwatch-agent.service 的 ExecStart
#   （支持 -server/-token/-state-dir/-name）→ daemon-reload → restart；改名推荐直接后台改
```

### 3.4 批量安装 12 台（batch-install-probes.sh）

**免密 SSH 由脚本自动完成**（无需手工前置）：中心无 SSH 密钥时自动生成 ed25519；对尚未免密的主机自动 `ssh-copy-id` 下发公钥——统一密码时交互只输入一次，或用环境变量非交互提供（`NW_PROBE_PASS='密码' ./batch-install-probes.sh ...`）。单台控制台直装也可用 `NW_SSH_PUBKEY="$(cat ~/.ssh/id_ed25519.pub)" ./install-agent.sh ...` 让中心即刻免密。随后：

```bash
# probes.csv 每行：IP,SSH用户,名称[,端口]（默认 root/22，# 注释）
./batch-install-probes.sh probes.csv http://10.8.14.200 <注册令牌>
```

逐台 SSH 检查 → scp 分发 → 远程安装（名称随注册上报）；SSH 失败跳过并汇总，**重跑安全**（已装的复用身份）。

### 3.5 安装后配置（全部在管理后台，免登录探针）

| 步骤 | 入口 | 要点 |
|---|---|---|
| 绑定线路+分组 | 探针管理 | **先绑定再启用**（绑定前历史不按线路归档）；外网服务器探针切"外网组" |
| 命名 | 探针管理 → ⚙运维 | 如"1楼-东配线间"，告警邮件显示用 |
| SSH 凭据 | ⚙运维 或页面底部批量导入 | 单台填主机/端口/用户/密码；CSV 每行 `匹配键,SSH主机,用户,密码[,端口]`（匹配键=ID 前缀或主机名）；AES-256-GCM 加密落库；配好后可测试连接/重启服务/网页终端/远程命令 |
| 探测参数下发 | 系统设置 → 探测配置 | 默认值即实测可用值；约 60s 下发；注册令牌同页 |
| 测速 | 系统设置 → 采集与测速 | Ookla 节点绝对值差异大，怀疑不准用 HTTP 引擎交叉验证；契约带宽务必填真实值（带宽告警阈值） |
| 外网组（官网监控） | 探针管理切组 + 探测配置 → 外网探测组 | 中心可达三方案（公网映射/VPN/FRP）原 docs/04 §3.1，见 AGENTS.md §14；证书 <15 天 P2 提醒 |
| 版本升级 | 探针管理"版本发布与升级"卡 | 上传（SHA256）→ 选目标版本 → ⚙运维"升级到 ×.×"；**灰度：先 1 台观察 10 分钟** |

### 3.7 部署相关故障排查

| 现象 | 处置 |
|---|---|
| 探针不出现在后台 | 核对令牌（§3.2 优先级）；探针上 `curl http://<中心>/healthz`；`journalctl -u netwatch-agent` |
| 反复注册新 ID（多行/绑定丢失） | `/var/lib/netwatch-agent/identity.json` 丢失或属主不对；修正后重启，旧行在后台删除（告警自动收口） |
| 服务起不来（中心/探针） | `journalctl -u netwatch-server|netwatch-agent`；核对 unit 内 DB 口令；探针可重跑安装脚本（幂等） |
| 大屏打不开 | 确认 `/opt/netwatch/web/dist/index.html` 存在（重新构建并同步） |
| 日志出现 clock skew | 探针时钟快于中心 >2 分钟 → 校时/配 NTP |

## 4. 安全要点（部署必读）

- 全部 VM 与中心配置 NTP（见 §3.1）；
- SSH 主密钥 `/opt/netwatch/data/ssh-master.key`（0600）**备份必带**，丢失则已存探针密码全部作废；
- PG/VM 仅本机监听；`.pg-pass`/`.enroll-token`/`ssh-master.key` 均 0600；
- 大屏 `#/screen` 公开只读，可由防火墙限源。
