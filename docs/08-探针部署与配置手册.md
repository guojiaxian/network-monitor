# 08 · 探针部署与配置手册

> 读者：现场实施与运维人员
> 配套：《04-运维手册》（中心端部署/升级/备份/故障处置）《06-用户操作手册》（日常使用）《07-现场功能测试报告》（实测依据）

## 1. 探针工作原理（部署前必读）

| 事项 | 说明 |
|---|---|
| 形态 | 单二进制 `netwatch-agent` + systemd 服务，**无入站端口**，仅出站 HTTP 访问中心 |
| 数据流 | 探测 → 批量上报中心 `/api/agent/metrics` → 中心判定告警；配置反向：探针**每 30s** 拉取一次（改配置后约 30~60s 生效） |
| 身份 | 首次启动凭**注册令牌**注册获得探针 ID，持久化到 `/var/lib/netwatch-agent/identity.json`；**重启/断电复用同一身份**（名称、绑定、SSH 凭据均保留）。身份文件丢失会自动重注册为新 ID，旧行需在后台删除 |
| 分组 | **内网组**（默认）：绑定线路后，测网关 + 公网多目标（ICMP/TCP/DNS/HTTP）+ 定时测速；**外网组**：部署在外网服务器，ping 官网域名 + HTTPS 访问官网 + 证书剩余天数检测 |
| 未绑定探针 | 内网组探针未绑定线路时不产生线路数据，总览页出现"未绑定"警告；外网组探针不计入该警告 |
| 资源要求 | 1C / 1G 内存 / 磁盘 <1GB 即可（10.8.14.201 实测）；OS 为银河麒麟 V10 实测通过，RHEL 系通用；x86_64 / aarch64 均支持 |
| 时间要求 | **必须 NTP 对时**。样本时间戳由探针产生，快于中心 >2 分钟会被钳位并记日志 `clock skew`（安装脚本偏差 >30s 会自动配 chrony） |

探针上跑什么探测、间隔多少，全部由中心**统一下发**（系统设置 → 探测配置），装完机后**无需登录探针改任何配置**。

## 2. 部署前准备（中心端）

1. **中心端健康**：探针网络能通中心——`curl http://10.8.14.200/healthz` 返回 `ok`（生产监听 **80 端口**；新装环境用 install-server.sh 默认为 8080，以实际 `NW_LISTEN` 为准）。
2. **取得注册令牌**（三处任一，值相同）：
   - `cat /opt/netwatch/.enroll-token`（生产机已存，0600）；
   - `grep NW_ENROLL_TOKEN /etc/systemd/system/netwatch-server.service`（新装环境以此为准，安装脚本完成时也会打印一次）；
   - 管理后台 → 系统设置 → 探测配置 → "注册令牌"（此处修改即全局更换）。
   - **令牌轮换**：更换后旧探针凭证不失效，仅影响**新**探针注册；建议 12 台装完后更换一次。
3. **线路与楼层先建好**：管理后台 → 线路配置（手工逐条或 CSV 批量导入，标准格式见《06》§4；**注意首列表头为"楼层名"**，非标准表头会被当数据行）。
4. **拿到探针二进制**：交付包 `deploy/netwatch-agent`（自包含，现场零下载）；或仓库 `make build` 产物 `bin/netwatch-agent`。

## 3. 单台安装（install-agent.sh）

探针 VM（root）上执行：

```bash
./install-agent.sh <中心地址> <注册令牌> [探针二进制] [探针名称]
# 生产示例（二进制与脚本同目录时第 3 参数可省略）：
./install-agent.sh http://10.8.14.200 $(cat 中心侧/opt/netwatch/.enroll-token 的值) "" "2楼-东配线间"
```

| 参数 | 说明 |
|---|---|
| 第 1 参数 | 中心地址，如 `http://10.8.14.200`（生产 80 端口免端口；8080 部署写 `http://<IP>:8080`） |
| 第 2 参数 | 注册令牌 |
| 第 3 参数 | 探针二进制路径；缺省按"脚本同目录 `netwatch-agent` → 包内 `bin/`"自动查找 |
| 第 4 参数 | **探针名称**（如"2楼-东配线间"），注册后后台直接显示；同时自动设置 VM 主机名（非 ASCII 自动转 ASCII 形式）——**克隆模板部署必传，避免同名** |

脚本自动完成六步（约 1 分钟，**可重复执行**——重复安装只覆盖二进制与 service 并重启，身份 identity.json 保留不变）：

1. 基础检查（root / 架构 / systemd）；
2. 中心连通性检查（`/healthz`）；
3. **与中心对时**（偏差 >30s 自动安装并启用 chrony，再复查）；
4. 安装二进制到 `/usr/local/bin/netwatch-agent`、写 systemd 服务（`CAP_NET_RAW` 授权用于 ICMP，`Restart=always` 开机自启/崩溃自拉起）；
5. **注册确认**（等待最多 30s，成功输出 `registered as agent <id>`；已有身份则显示"复用"）；
6. 打印服务状态与下一步提示。

装完后的日常运维命令（探针上）：

```bash
systemctl status netwatch-agent                    # 状态
journalctl -u netwatch-agent -f                    # 实时日志（注册成功行：registered as agent）
systemctl restart netwatch-agent                   # 重启（身份/绑定/凭据保留，无需重注册）
```

**改中心地址/令牌/名称**：编辑 `/etc/systemd/system/netwatch-agent.service` 的 `ExecStart` 行（支持 `-server/-token/-state-dir/-name` 四个参数）→ `systemctl daemon-reload && systemctl restart netwatch-agent`。改名也可直接在后台"探针管理 → ⚙ 运维"完成（推荐，无需登录探针）。

## 4. 批量安装 12 台（batch-install-probes.sh）

在**操作机**（可 SSH 到全部探针 VM）上执行，前置：操作机对各探针**免密 SSH**（`ssh-copy-id` 逐台分发一次即可）：

```bash
# probes.csv 每行：IP,SSH用户,名称[,端口]（默认 root/22，# 开头为注释行）
cat > probes.csv <<'CSV'
10.8.20.11,root,2楼-东配线间
10.8.21.11,root,3楼-西配线间
10.8.22.11,root,4楼-东配线间
CSV
./batch-install-probes.sh probes.csv http://10.8.14.200 <注册令牌>
```

脚本逐台：SSH 连通检查 → scp 分发二进制与安装脚本 → 远程执行 install-agent.sh（名称随之注册）→ 打印每台结果；任一台 SSH 失败会跳过并在最后汇总提示，**重跑安全**（已装的会复用身份）。

## 5. 安装后配置（全部在管理后台完成，免登录探针）

### 5.1 绑定线路与分组（核心步骤）

管理后台 → **探针管理**（`#/probes/manage`）：

- **绑定线路**：每行"绑定线路"下拉选择对应楼层线路。**先绑定再正式启用**——绑定前的历史数据不按线路归档。绑定后总览页该线路卡即有状态/心跳/时延/丢包；
- **分组**：内网组探针选"内网组"（默认）；阿里云等外网服务器探针切"外网组"（切换后该探针按官网探测配置运行，约 30s 生效）；
- 确认结果去 **探针状态** 页（`#/probes`，只读，15 秒自动刷新）：全部在线、心跳时间在 1 分钟内、出口源 IP/默认网关符合预期。

### 5.2 探针命名

探针管理 → 每行 **⚙ 运维** 展开区 → "探针名称"填写（如"1楼-东配线间"）→ 保存。名称用于探针列表、告警邮件与处置指引，建议与楼层/位置对应。

### 5.3 SSH 运维凭据（零接触运维）

- **单台**：⚙ 运维 展开区填 SSH 主机（管理 IP）/端口/用户/密码（留空密码=不改）→ 保存；
- **批量**：页面底部"SSH 运维凭据批量导入"卡（默认折叠，点"展开导入"），CSV 每行 `匹配键,SSH主机,用户,密码[,端口]`，匹配键 = 探针 ID 前缀或注册主机名，`#` 为注释；密码 AES-256-GCM 加密落库；
- 配好后展开区内可用：**测试连接** / **重启探针服务**（探针异常一键救援，身份保持）/ **🖥 终端**（网页 SSH，仅管理员，全程审计）/ **远程命令**（临时诊断）。

### 5.4 探测参数下发（内网组）

系统设置 → **探测配置**：Ping/TCP/DNS/HTTP 间隔与超时、各类目标列表、注册令牌。修改保存后约 **60s** 下发到全部内网组探针。目标配置经验（来自《07》实测）：

- **ICMP 目标**：保留 3 个公共 DNS 多目标投票；某目标对特定线路长期 100% 丢包（如 114.114.114.114 对 10.8.14.0/23 出口实测不通）不影响判定（按目标丢包**下中位数**），但建议替换为对该线路可 ping 的地址以获得更准的丢包统计；
- **TCP/HTTP 目标**：qq.com/baidu.com 默认即可；HTTP 目标返回状态码与证书天数入探测历史；
- 默认值即现场验证过的取值，无特殊需求不必调整。

### 5.5 测速配置

系统设置 → **采集与测速** → 测速计划：引擎/间隔/超时/HTTP 下载源；手动单线测速在线路配置页"⚡ 立即测速"（周期开关关闭时也可用）。实测经验：

- **Ookla 公共节点绝对值差异大**（昆山节点实测 0.3~1 Mbps，同线路 HTTP 实测 24.7 Mbps）——测速绝对值仅供参考，怀疑不准时用 HTTP 引擎交叉验证或更换节点池；
- 默认 HTTP 下载源为已验证有效的微信安装包地址（2026-11-06 更新，旧 dldir1.qq.com 源已 404）；纯 IPv4 内网若单源挂起可补充 IPv4 直连地址；
- 测速结果低于契约带宽 70%（连续 2 次）触发 P2"带宽不达标"，**契约带宽务必填真实值**（线路配置页）。

### 5.6 外网组探针（阿里云等 · 官网监控）

1. 外网服务器安装**同一个**探针（同 §3，中心地址用外网可达形式——公网映射/VPN/FRP 三方案见《04》§3.1）；
2. 探针管理 → 该探针分组切"**外网组**"；
3. 系统设置 → 探测配置 → **外网探测组**：HTTPS 目标（官网 URL）+ ICMP 目标（官网域名）+ 间隔，保存后 30s 下发；
4. 行为：全部外网探针 HTTPS 失败 → P1"网站从外网不可达"；部分失败 → P2 冲突提示；证书剩余 <15 天 → P2 提醒。总览页"外网 → 内网"区块查看结果。

### 5.7 探针版本升级

探针管理 → "版本发布与升级"卡：上传新版二进制（版本号 + 文件，≤256MB，中心记 SHA256）→ 选择**目标版本** → 回探针列表展开 ⚙ 运维 → "升级到 ×.×"。探针 30s 内自动下载、SHA256 校验、原子替换、重启，失败不影响原版本。**灰度：先升 1 台观察 10 分钟再全量**。升级排队时探针列表版本列显示"当前 → 待升级"。

## 7. 故障排查（探针侧）

| 现象 | 判断 | 处置 |
|---|---|---|
| 探针不出现在后台 | 令牌不符 / 网络不通 / 中心未启动 | 核对令牌（§2 三处）；探针上 `curl http://<中心>/healthz`；`journalctl -u netwatch-agent` 看注册报错 |
| 探针反复注册新 ID（后台出现多个行、绑定凭据丢失） | `/var/lib/netwatch-agent/identity.json` 丢失或目录属主不对（服务以 root 运行应为 root 属主） | 修正属主/权限后重启；旧行在探针管理中**删除**（其盲区告警自动收口）。2026-11-06 版本已修复"重启必重注册"缺陷，若复现请确认探针二进制为修复版 |
| 探针在线但线路长时间"未知"/无数据 | 未绑定线路 | 探针管理绑定线路；总览未绑定警告核对 |
| P0 监控盲区 | 探针停机 / VM 宕机 / 与中心失联 | `systemctl status netwatch-agent`；VM 控制台查网络；计划内维护先到 系统设置 → 告警策略 建静默 |
| 日志出现 `clock skew` | 探针时钟快于中心 >2 分钟 | 校时：`chronyc sources` 确认 NTP 源；手工 `date -s` 应急；根治=全部 VM 配 NTP |
| 测速值异常低或为 0 | Ookla 节点差异 / 下载源失效 / IPv6 挂起 | 线路详情看 7 天趋势；HTTP 引擎交叉验证（curl 大文件）；更换下载源或节点池（§5.5） |
| 单探针线路停探针时"线路中断"先于"盲区"出现 | 设计行为（单探针经线路汇报，中断约 45s 先于盲区 60s） | 无需处理；多探针线路则表现为 P2"探针数据冲突"指向故障探针 |
| 服务起不来（探针 VM） | 二进制缺失 / systemd 单元损坏 | 重跑 install-agent.sh（幂等）；`journalctl -u netwatch-agent -n 50` |

## 8. 安全与维护要点

- **SSH 凭据**：AES-256-GCM 加密存储，主密钥 `/opt/netwatch/data/ssh-master.key`（0600）——**备份必须包含**，丢失则已存密码全部作废需重录；建议为探针建专用运维账号而非 root，定期在 ⚙ 运维 中改密；
- **重装/更换探针 VM**：`/var/lib/netwatch-agent/identity.json` 拷贝到新机同路径可**保留原身份**（绑定/凭据/名称不动）；不拷贝则按新探针注册，旧行记得删除；
- **令牌与端口**：注册令牌定期轮换（探测配置 Tab）；中心端口变更后需逐台改探针 service 的 `-server` 参数（§3）并 daemon-reload；
- **防误告警**：对探针 VM 做计划内维护（迁移/内核升级）前，先到 系统设置 → 告警策略 建静默窗口，避免 P0/P1 误报打扰。
