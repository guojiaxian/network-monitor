# NetWatch 用户操作手册

> 读者：网络管理员、值班人员
> 管理端地址：`http://<中心IP>:8080`　大屏地址：`http://<中心IP>:8080/#/screen`

---

## 1. 角色说明

| 角色 | 权限 |
|---|---|
| 管理员 | 全部功能：配置、线路维护、用户管理、设置修改 |
| 观察者 | 只读：查看总览/告警/报表/曲线，不能修改任何配置 |

值班人员建议使用观察者账号；系统设置中的"操作审计日志"会记录所有变更操作。

## 1.1 界面导航（左侧栏分两组）

侧栏按"看"与"管"分成两组，各页面职责单一：

- **监控展示**（只看数据，不含任何配置）：总览 · 告警中心 · 探针状态（探针健康/版本/心跳只读总览）· 探测历史 · 报表 · 大屏展示（新窗口）；
- **配置管理**（改配置、做运维）：线路配置（楼层/线路/CSV 导入/手动测速）· 探针管理（绑定/分组/SSH 运维/版本升级/凭据导入）· 系统设置。

系统设置页内按域分 6 个标签页（均可直达）：**通知渠道**（SMTP、钉钉/企微）· **告警策略**（阈值收件组、静默窗口）· **探测配置**（内网组下发、外网探测组、内网服务监控）· **采集与测速**（测速计划、SNMP）· **报表推送** · **用户与审计**（用户管理、操作审计日志）。

## 2. 首次初始化（管理员，仅一次）

打开管理端 → 进入初始化向导：

1. **创建管理员账号**（用户名 ≥2 字符，密码 ≥8 位）；
2. **填写 SMTP**（服务器、端口、发件人、收件人；SSL 勾选对应 465 端口），保存后到"系统设置 → 通知渠道 → 测试邮件"验证；
3. **导入线路清单**（CSV，可跳过）：每行 `楼层名,子网CIDR,线路名,公网IP,下行Mbps,上行Mbps`，后三列可省略，楼层不存在自动创建；
4. 探针装好后，在「探针管理」中把每台探针**绑定到对应线路**——绑定后总览即按线路展示。

## 3. 总览页

- **状态卡**：每张卡对应一条宽带线路，显示楼层、子网、出口公网 IP、契约带宽、实时时延/丢包/测速值。
- **状态灯语义**：🟢 正常　🟡 降质　🔴 线路中断 / 楼层中断（呼吸闪烁）　🟣 监控盲区　⚪ 未知（探针未绑定）。
- **心跳条**：卡片中部的小竖条，每格代表一次公网探测，绿=成功红=失败——一眼看出最近 30 次探测的连续性。
- 点击卡片进入**线路详情**：24 小时时延与连通率曲线、7 天测速曲线（红线为契约带宽参考线）。
- 页面每 10 秒自动刷新；顶部统计卡汇总全局正常/异常/盲区数量。

## 3.1 外网视角 · 官网可达性

总览页"🌐 外网视角"区块展示从阿里云等外网服务器看到的**官网状态**：每台外网探针 ping 官网域名并 HTTPS 访问官网（显示时延与 HTTPS 正常/失败）。

| 告警 | 含义 | 处置 |
|---|---|---|
| P1 网站从外网不可达 | **全部**外网探针 HTTPS 都失败——对互联网用户官网大概率已不可用 | 立即检查 Web 服务、防火墙公网映射、出口线路 |
| P2 外网探针冲突 | 部分外网探针报失败 | 优先查异常探针服务器自身网络 |
| P2 证书即将过期 | HTTPS 证书剩余 <15 天 | 尽快续签并部署 |

配置入口：系统设置 → 探测配置 → "外网探测组"（HTTPS 目标即官网地址）；探针归属在探针管理的分组下拉切换。

## 3.2 监控视角说明（总览页三大区块）

总览页按方向分组呈现三块内容：

1. **🏢 内网 → 内网 · 内网服务**：中心服务器自己当探针（Uptime Kuma 模式），监控内网关键服务（OA、业务系统、核心交换机等）。在"系统设置 → 探测配置 → 内网服务监控"添加目标（`名称,类型,目标,间隔秒`，类型 tcp/http/icmp），连续 3 次失败触发 P2"内网服务不可达"。
2. **🔀 内网 → 外网 · 宽带线路**：12 条宽带线路状态卡片墙（本系统主体）。
3. **🌐 外网 → 内网 · 官网可达性**：阿里云等外网探针访问官网（含证书检测）。

三个方向独立告警、独立统计，覆盖"内网服务挂没挂 / 出口通不通 / 外网进得来吗"完整闭环。

## 4. 线路配置（线路与楼层维护）

- **楼层**：先建楼层（名称 + 子网 CIDR）。
- **线路**：填线路名、契约带宽（契约带宽用于带宽不达标告警的阈值，务必填写真实值）、关联楼层。**出口公网 IP 无需手工填写**——绑定的探针会自动探测线路出口 IP 并随心跳回填（宽带重拨换 IP 后自动跟随；手工改写的值也会在下一轮心跳被探测值纠正，仅在所有回显服务都不可达时手工值才作为兜底显示）。
- **CSV 批量导入**：适合 12 条线路一次录入。
- **⚡ 立即测速**：对该线路手动触发一次测速（全网串行排队，30 秒内开始执行）。

## 5. 探针管理

- 探针的**健康状态**（在线/离线、出口源 IP、网关、最后心跳、版本）在"监控展示 → 探针状态"页只读查看（15 秒自动刷新）；本页专注管理操作。
- 新探针注册后自动出现在列表（"未绑定"状态），用下拉框绑定到线路即可。
- **探针名称**：点每行"⚙"可设置别名（如"1楼-东配线间"），列表与告警处置时更直观。
- **SSH 远程运维（免逐台登录）**：在"⚙"面板填写探针管理 IP/端口/用户/密码，或用页面底部"SSH 运维凭据批量导入"卡的**批量导入**（默认折叠，点"展开导入"）（CSV：`匹配键,SSH主机,用户,密码[,端口]`，匹配键为探针 ID 前缀或主机名；密码 AES-256-GCM 加密存储）。配好后可：
  - **🖥 终端**：打开**网页版 SSH 终端**（基于开源 xterm.js，与阿里云网页终端同体验）——直接输命令操作探针，窗口可自适应尺寸，关闭页面即断开；
  - **测试连接**：验证 SSH 通不通；
  - **重启探针服务**：探针 agent 异常时的一键救援；
  - **远程命令**：临时在探针上执行诊断命令（输出直接显示，操作进入审计日志）。
  终端与远程命令仅管理员可用，每次打开均记录审计日志。
- 探针的全部探测参数（目标、频率、超时）本来就在"系统设置"统一下发，**装完机后无需再登录探针 VM 做任何配置**。
- 版本列显示"当前版本 → 待升级版本"（升级排队时）。
- **版本升级**：在"版本发布与升级"卡上传新版二进制并选好**目标版本** → 回探针列表展开"⚙ 运维"点"升级到 ×.×"。建议先升 1 台观察 10 分钟再全量。

## 6. 告警中心

| 级别 | 含义 | 首要处置 |
|---|---|---|
| P0 监控盲区 | 探针失联，该楼层失去监测 | 检查探针 VM；计划内维护请先建静默 |
| P1 线路中断 | 楼层网关正常但公网全断 → **线路/出口故障** | 拨打线路商报障 |
| P1 楼层中断 | 楼层网关不可达 → **楼内故障** | 查楼内交换机/网关，勿报线路商 |
| P2 线路降质 | 丢包/时延持续偏高 | 观察线路详情曲线，持续两个窗口再报障 |
| P2 带宽不达标 | 测速连续 2 次低于契约 70% | 结合测速曲线判断，必要时报障 |
| P2 数据冲突 | 多探针线路部分报中断、部分正常 | 线路大概率正常，优先检查报中断探针的 VM 与位置 |

- 筛选"进行中/已恢复/全部"；恢复类通知自动发送，无需人工关闭。
- **IM 推送**：系统设置 → 通知渠道 → IM 告警通道，填入钉钉/企业微信群机器人 Webhook 即可让告警进群（P0/P1 恒推、P2 按开关），配好后点"测试钉钉/测试企微"验证。
- **静默窗口**：线路割接等计划维护前，先到"系统设置 → 告警策略"创建静默（选线路、填时长与原因），告警中心页首有快捷跳转，避免真实告警打扰。注意：删除静默后最多 30 秒内恢复告警判定。

## 6.1 探测历史（PRTG 风格逐条记录）

「探测历史」页可逐条查看每个探针的**原始探测记录**（数据保留 90 天）：

- **过滤条件**：探针（含中心内置监控）→ 类型（Ping/TCP/DNS/HTTP/内→内/测速）→ 目标 → 时间范围（30 分钟~7 天）；
- 每条记录：时间、目标、结果（成功/失败着色）、时延，HTTP 类型额外显示状态码与证书剩余天数，Ping 区分网关/公网；
- 可**导出 CSV**（Excel 打开），常用于故障复盘与向线路商举证；
- 条数上限 5000，超限时缩小时间范围。曲线图看趋势，本页看明细，两者互补。

## 7. 报表

- 每日 08:00 自动生成日报、每周一 08:30 自动生成周报（可在系统设置 → 报表推送调整/关闭）并邮件推送。
- 「报表」页可查看历史报表、手动生成立即统计（日报=近 24h、周报=近 7 天）、导出 CSV 存档。

## 8. 测速计划

- 系统设置 → 采集与测速 → 测速计划：默认每线每 30 分钟、**全局串行**（同一时刻只有一条线在测速），不影响办公。
- 引擎建议：默认 Ookla（自动就近选联通节点）；若单位网络限制 Speedtest，可切换 HTTP 大文件引擎并配置下载源。
- 业务高峰敏感时可调大间隔（如 60 分钟）。

## 9. 大屏（值班室）

- 地址 `#/screen`，无需登录，只读；1080P/4K 自适应，10 秒自动刷新。
- 主区 12 格状态墙（异常呼吸闪烁），右上角实时时钟，底部当前告警滚动。
- 建议浏览器全屏（F11）并关闭显示器休眠。

## 10. 常见问题

**Q：某条线路显示"未知"？** 该线路尚未绑定探针，到探针管理完成绑定。

**Q：告警邮件谁会收到？** 系统设置 → 告警策略的收件组：P0/P1 与 P2 可分别配置，留空则发给默认收件人。

**Q：为什么测速值和运营商宣传带宽不同？** 测速受对端节点、时段负载影响；以线路详情页的 7 天趋势与"测速峰值"为准，单次结果仅供参考。

**Q：可以只测速不告警吗？** 可以：关闭测速计划即不测速不判带宽；连通性告警与测速相互独立。

**Q：一条线路可以绑两台探针吗？** 可以，且推荐对重要楼层做双探针交叉验证：两台都报中断才触发 P1 线路中断；只有一台报中断时产生 P2"数据冲突"提示（多为探针本机问题），避免误报。

**Q：想看每条线路的真实流量占用（不是测速）？** 让网络管理员在防火墙上开通只读 SNMP，然后在"系统设置 → 采集与测速 → SNMP"填设备 IP 与团体字、把 WAN 接口映射到线路。线路详情页会出现 24 小时真实上下行流量曲线。

**Q：忘记管理员密码？** 由另一位管理员在"系统设置 → 用户与审计"重建账号；仅有唯一管理员时，联系运维用 SQL 重置（见运维手册）。
