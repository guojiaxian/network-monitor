# 09 · 数据库结构与运维手册

> 读者：系统管理员
> 配套：《04-运维手册》（中心端部署/升级/备份总览）《08-探针部署与配置手册》《06-用户操作手册》
> 现状基线（生产 10.8.14.200，2026-11-05 部署）：**PostgreSQL 10.5**（yum 安装，`/var/lib/pgsql/data`，仅本机 5432，hba 密码认证）+ **VictoriaMetrics v1.102.1**（`:8428` 仅本机，`-retentionPeriod=90d -memory.allowedPercent=20`，数据目录 `/opt/netwatch/vmdata`）。本文所有结构与行为均核对自 `internal/server/store.go` / `tsdb.go` 等源码与生产实测。

## 1. 存储总览：双库分工

| 存储 | 存什么 | 特点 |
|---|---|---|
| **PostgreSQL**（库 `netwatch`） | 业务事实：楼层/线路/探针/告警/静默/报表/用户/审计/设置/版本发布 | 全部配置的**唯一权威来源**；重启不丢 |
| **VictoriaMetrics** | 时序样本：全部探测结果曲线（ping/tcp/dns/http/测速/SNMP 流量/内置监控） | 只追加；**90 天自动过期**；丢了不影响配置与告警历史，仅丢历史曲线 |

其他状态位置（不在这两个库里，运维须知）：
- **Web 会话**：server 进程内存——重启后所有登录失效（需重新登录，属设计）；
- **SSH 凭据主密钥**：`/opt/netwatch/data/ssh-master.key`（0600）——密文在 PG `probes.ssh_pass_enc`，**主密钥丢失则全部密码作废**；
- **探针本地**：`/var/lib/netwatch-agent/identity.json`（身份）+ `cache.jsonl`（断网缓存，上限 48MB 轮转，恢复后按 500 条/批补传）。

**生产实测盘点（2026-11-06）**：全库 8.4MB；各行数 floors/lines/probes=1、alerts=17（演练告警，全 resolved）、audit=50、users=2、reports=1、settings=9、agent_releases=0；vmdata 348K（单探针 1 天）。

## 2. PostgreSQL 表结构详解（10 张表）

### 2.1 关系图

```
floors ──< lines ──< probes          （外键：线路.楼层 / 探针.线路）
             │  ＼
             │   └──< silences       （删线路 → 级联删静默）
             └── 弱关联：alerts.line_id / alerts.probe_id（普通列，无外键，删主不级联）
独立表：settings / users / audit / reports / agent_releases
```

### 2.2 floors（楼层/子网）

| 列 | 类型 | 说明 |
|---|---|---|
| id | SERIAL PK | |
| name | TEXT | 楼层名（如"3楼"） |
| cidr | TEXT | 子网 CIDR（如 10.8.20.0/24），展示用 |
| created_at | TIMESTAMPTZ | |

维护入口：线路配置页。**删除楼层** → 关联线路的 `floor_id` 置 NULL（`ON DELETE SET NULL`），线路不删。

### 2.3 lines（宽带线路）

| 列 | 类型 | 说明 |
|---|---|---|
| id | SERIAL PK | 被 probes/silences/alerts 引用 |
| name | TEXT | 线路名（唯一性由后台校验，非库约束） |
| isp | TEXT | 运营商，默认'联通' |
| public_ip | TEXT | 出口公网 IP（2026-11-06 起可由探针自动探测回填） |
| contract_down_mbps / contract_up_mbps | INT | 契约带宽，**带宽不达标告警阈值依据**，0=无契约（不判） |
| floor_id | INT → floors | ON DELETE SET NULL |
| created_at | TIMESTAMPTZ | |

删除线路 → 绑定探针自动解绑（SET NULL）、该线路静默**级联删除**（CASCADE）、历史告警行保留（无外键）。

### 2.4 probes（探针）

| 列 | 类型 | 说明 |
|---|---|---|
| id | **TEXT** PK | 探针 ID（注册时生成，如 16 位 hex），由探针持久化复用 |
| secret | TEXT | 探针上报凭证（注册时下发，随每次上报鉴权） |
| hostname / os / arch / version / source_ip / gateway | TEXT | 注册与心跳时自报 |
| name | TEXT | 后台设置的显示名（如"1楼-东配线间"） |
| line_id | INT → lines | 绑定线路；ON DELETE SET NULL |
| grp | TEXT | `internal`（内网组，默认）/ `external`（外网组） |
| ssh_host / ssh_port / ssh_user / ssh_pass_enc | | 零接触运维凭据；**密码仅存 AES-256-GCM 密文** |
| pending_version | TEXT | 已下发待升级的版本号（升级完成后清空） |
| enrolled_at / last_seen | TIMESTAMPTZ | 注册时间 / 最后心跳（盲区判定依据：>60s） |

**删除探针**（探针管理页）→ 其盲区告警与幽灵状态自动收口；探针若仍在运行会以新 ID 重注册（身份在探针本地）。

### 2.5 alerts（告警，唯一带索引的大表）

| 列 | 类型 | 说明 |
|---|---|---|
| id | BIGSERIAL PK | |
| fingerprint | TEXT | 同一问题唯一指纹（kind+对象维度），用于状态翻转 |
| severity / kind | TEXT | P0/P1/P2；kind=blind/line_down/floor_down/degraded/speed_low/probe_conflict/site_down/site_conflict/cert_expiring/monitor_down |
| title / body | TEXT | 标题与详情（邮件正文同源） |
| probe_id / line_id | TEXT / INT | 弱关联（无外键） |
| starts_at / ends_at | TIMESTAMPTZ | 触发/恢复时间 |
| status | TEXT | `firing` / `resolved` |

索引：`idx_alerts_status(status, starts_at DESC)`（列表页"进行中/已恢复"查询）。**恢复=更新原行**（status→resolved、补 ends_at），不新增行。无自动清理。

### 2.6 settings（全部可配置项，JSONB）

| key | 内容 | 后台入口（重排后） |
|---|---|---|
| agent_config | 内网组探测下发（四类间隔/超时/目标 + version 乐观锁） | 系统设置 → 探测配置 |
| agent_config_external | 外网组官网探测配置 | 系统设置 → 探测配置 |
| internal_monitors | 内→内内置监控（enabled + items[]） | 系统设置 → 探测配置 |
| smtp | 邮件服务器（**密码 GET 时掩码 `__SET__`**，PUT 空或占位符=保留原值） | 系统设置 → 通知渠道 |
| notify_channels | 钉钉/企微 webhook | 系统设置 → 通知渠道 |
| alert_settings | 告警阈值 + P0P1/P2 收件组 | 系统设置 → 告警策略 |
| speed_settings | 测速引擎/间隔/超时/HTTP 源 | 系统设置 → 采集与测速 |
| snmp_settings | SNMP 采集 + 接口映射 | 系统设置 → 采集与测速 |
| report_settings | 日报/周报计划 | 系统设置 → 报表推送 |
| agent.enroll_token | 注册令牌（**存在即覆盖** systemd 单元里的 `NW_ENROLL_TOKEN`；生产当前未落库，实际生效值为 unit 环境变量） | 系统设置 → 探测配置 → 注册令牌 |

种子：首次启动自动写入 9 个默认键（`ON CONFLICT DO NOTHING`，不覆盖已有值）。API 层有白名单：PUT 只接受以上 10 键，未知键静默忽略。⚠️ **手工改 JSONB 的风险**：`agent_config*` 内含 `version` 字段做下发版本号，手改不递增则探针**不会**应用新配置——改配置请走后台。

### 2.7 其余表

| 表 | 用途 | 要点 |
|---|---|---|
| users | 后台账号 | username UNIQUE；password_hash（bcrypt）；role=`admin`/`viewer`（viewer 非 GET 全 403）。**无会话表**（会话在内存） |
| reports | 日报/周报 | kind=day/week；period 起止；**data JSONB** 存整份统计（可用率/时延/丢包/测速/告警数），导出 CSV 由其生成 |
| silences | 静默窗口 | line_id NULL=全部线路；ON DELETE CASCADE（删线路连带删）；到期自然失效 |
| audit | 操作审计 | 每个写操作一行（用户/动作/结果）；后台"用户与审计"页显示最近 100 条；**无自动清理** |
| agent_releases | 探针版本发布 | version/os/arch/sha256/filename/size_bytes；文件本体在 `/opt/netwatch/data/agent-releases/<版本>/`（库只记元数据） |

## 3. VictoriaMetrics 指标体系

写入方：探针样本经 server 转换入库（`tsdb.go`）；SNMP 流量与内置监控由中心自采写入。

| 指标 | 含义 | 标签 |
|---|---|---|
| nw_ping_rtt_ms / nw_ping_ok / nw_ping_loss_pct | ICMP 时延/成败/丢包率 | probe, line, class=`gw`\|`public`, target |
| nw_tcp_rtt_ms / nw_tcp_ok | TCP 连通 | probe, line, target |
| nw_dns_rtt_ms / nw_dns_ok | DNS 解析 | probe, line, target |
| nw_http_ttfb_ms / nw_http_ok / nw_http_code / nw_http_cert_days | HTTP 首字节/成败/状态码/证书剩余天数 | probe, line, target |
| nw_speed_down_mbps / nw_speed_up_mbps | 测速上下行 | probe, line, target |
| nw_snmp_in_bps / nw_snmp_out_bps | 防火墙 WAN 口真实流量 | line（中心采集） |
| nw_monitor_ok / nw_monitor_rtt_ms | 内→内内置监控 | monitor, type（中心自探，**无 probe 标签**） |

要点：
- `class=gw|public` 区分网关/公网探测——楼层中断与线路中断判定、探测历史页"网关/公网"分类都依赖它；
- **保留 90 天**自动过期；单探针 30 天 255 万样本实测约 25MB，磁盘无压力；
- **即时查询有 ~30s latencyOffset**（刚写入的数据查不到属正常，导出/区间查询不受影响）——回填数据后立即生成报表可能为空，稍等再试；
- 原生 API（`http://127.0.0.1:8428`）仅本机可访问；后台"线路详情/探测历史"已封装常用查询，无需直连。

## 4. 数据增长与保留策略

| 数据 | 增长量级（12 线路满配） | 自动清理 | 建议 |
|---|---|---|---|
| VM 时序 | 每线每天约 3~8 万样本；30 天全系统 <100MB | ✅ 90 天 | 无需管理；磁盘告警阈值可设 10GB |
| alerts | 每次故障 1~3 行；正常日 0 行 | ❌ | 每年手工归档一次即可（§5.4 配方） |
| audit | 每个变更操作 1 行（≈每天几行） | ❌ | 保留 1 年无压力；如需精简按时间删 |
| reports | 每日 1 行 + 每周 1 行（+手工） | ❌ | 保留全量（每行几 KB） |
| agent_releases | 每次发布 1 行 + 1 个二进制文件（数 MB） | ❌（文件随发布覆盖目录） | 旧版本可在发布后手工清理文件与行 |
| silences | 过期后仍留行 | ❌ | 少量无碍；可定期清过期行 |

## 5. 管理员日常运维

### 5.1 访问数据库的正确姿势

```bash
# 方式一：应用账号 + 口令文件（口令在 /opt/netwatch/.pg-pass，0600）
PGPASSWORD=$(cat /opt/netwatch/.pg-pass) psql -h 127.0.0.1 -U netwatch -d netwatch
# 方式二：本机 postgres 系统账号（peer 信任，无需口令）
su - postgres -c "psql netwatch"
```

**原则**：查询随意，**写操作能走后台就走后台**——后台写会同步处理下发版本、缓存、告警收口等联动逻辑，直改库不会。必须直改库的场景见 §5.4 配方（均已在现场验证）。

### 5.2 巡检命令集（建议每日）

```bash
systemctl is-active netwatch-server victoriametrics postgresql        # 三服务
curl -s http://127.0.0.1/healthz && curl -s http://127.0.0.1:8428/health   # 双库存活
pg_isready                                                            # PG 就绪
PGPASSWORD=$(cat /opt/netwatch/.pg-pass) psql -h 127.0.0.1 -U netwatch -d netwatch -t -A -c \
  "SELECT 'PG体积:'||pg_size_pretty(pg_database_size('netwatch'))||'  告警:'||(SELECT count(*) FROM alerts WHERE status='firing')||' firing'"
df -h /opt/netwatch /var/lib/pgsql                                    # 磁盘
journalctl -u netwatch-server --since today | grep -iE 'error|clock skew' | tail
```

### 5.3 备份与恢复

备份三件套（脚本见《04》§5，建议 crontab 每日 02:00）：**①** `pg_dump netwatch`（配置/告警/用户/审计全在里面）；**②** VM snapshot API 后拷快照目录（或直接备 `/opt/netwatch/vmdata`）；**③** `data/` 目录——**必须含 ssh-master.key**（丢了全部探针 SSH 密码作废），连同 `.pg-pass`、`.enroll-token`、systemd 单元一起存档。

恢复顺序：装好同版本 PG/VM → 建空库 `netwatch` 并恢复 dump → 还原 vmdata → 还原 data/（含 master.key，0600）→ 启动 server。**恢复后必做验证**：登录后台 → 总览有线路 → 探针状态页全部 online → 任一探针"测试连接"成功（验证 master.key 完好）。建议每季度做一次恢复演练。

### 5.4 常用 SQL 配方（直改库场景，均已实测）

```sql
-- ① 管理员密码重置（唯一管理员且密码遗失；只影响登录，监控数据全保留）
DELETE FROM users;   -- 然后刷新后台 → 自动进入初始化向导重建管理员

-- ② 清空演练/测试告警（先在页面确认无进行中真实告警）
DELETE FROM alerts;

-- ③ 清理压测/孤儿探针行（loadgen 探针固定前缀；后台删除亦可且会联动收口告警）
DELETE FROM probes WHERE hostname LIKE 'loadgen-%' OR name LIKE 'loadgen-%';

-- ④ 清理已过期静默窗口（不删也只是列表冗余，不产生副作用）
DELETE FROM silences WHERE ends_at < now();

-- ⑤ 查看设置清单与更新时间 / 某键内容
SELECT key, updated_at FROM settings ORDER BY updated_at DESC;
SELECT value FROM settings WHERE key='alert_settings';

-- ⑥ 用户角色调整（后台可做；直改用于救急）
UPDATE users SET role='viewer' WHERE username='xxx';

-- ⑦ 审计/报表精简（可选）
DELETE FROM audit WHERE created_at < now() - interval '365 days';
DELETE FROM reports  WHERE created_at < now() - interval '365 days';

-- ⑧ 告警月度统计
SELECT severity, kind, count(*) FROM alerts
WHERE starts_at > now() - interval '30 days' GROUP BY 1,2 ORDER BY 3 DESC;
```

### 5.5 结构变更（升级场景）

表结构变更由**中心端启动时自动执行**（`CREATE TABLE IF NOT EXISTS` + `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`，见 `store.go migrate()`），升级 server 即完成迁移，**无需手工跑 SQL**；历次新增列（探针名称/SSH 凭据/分组等）都是这样加的。降级旧版本二进制不影响兼容（列只增不改语义）。

### 5.6 数据库故障处置

| 现象 | 排查 | 处置 |
|---|---|---|
| server 起不来，日志连库失败 | `pg_isready`；`journalctl -u netwatch-server`；核对 unit 内 NW_DB 口令与 `.pg-pass` 是否一致 | 口令不一致→改回 unit；库损坏→§5.3 恢复 |
| PG 拒绝连接（too many clients） | `SELECT count(*) FROM pg_stat_activity;` | 排查异常连接方；默认 100 连接对本系统富余 |
| VM 写入失败/曲线断 | `curl 127.0.0.1:8428/health`；`df -h` 磁盘；`journalctl -u victoriametrics` | 磁盘满→清理或扩容（VM 数据可按 §4 量级评估）；探针侧不受影响（断网缓存自动补传） |
| 磁盘增长异常快 | `du -sh /opt/netwatch/vmdata /var/lib/pgsql`；VM 是否改过 retention | 调小 `-retentionPeriod`（重启 VM 生效）；PG 大表按 §5.4 ⑦ 清理 |
| 查询刚写入的数据为空 | 即时查询 ~30s 延迟 | 属正常（latencyOffset），稍后再查 |

### 5.7 安全基线

- PG/VM **仅本机监听**（5432/8428 不对网开放），PG hba 为本机密码认证——如无明确需要不要放开远程访问；
- `.pg-pass`、`.enroll-token`、`ssh-master.key` 均 0600 属主 netwatch，**备份文件同样收紧权限**（备份包含全部凭据，等同最高敏感级）；
- `psql` 直改（尤其 users/settings）属于绕过审计的操作：`audit` 表不会记录，建议手工操作后自行在变更记录中留痕；
- 库口令轮换：改 PG 角色口令后需同步改 unit 内 `NW_DB` 并 `daemon-reload + restart netwatch-server`。
