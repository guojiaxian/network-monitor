## 一句话方案

自研 Go 探针（每楼层子网 1 台精简 VM，出站流量经策略路由天然走本楼层宽带）→ 中心端（Go 服务 + VictoriaMetrics + PostgreSQL，Docker Compose 一键部署）→ Vue3 管理端（复用 Uptime Kuma MIT 组件与设计）+ 大屏 + 邮件告警；测速由探针直接对互联网进行（Ookla 公共节点协议实现 + HTTP 下载测速兜底，全局串行错峰调度）。

## 快速开始（中心端）

**推荐方案 A（原生 systemd，单业务服务器无需 Docker）**：

```bash
# 1. 构建全部产物
make build          # 后端二进制 + 前端 web/dist

# 2. 上传整个目录到中心服务器后执行
deploy/install-server.sh            # 安装到 /opt/netwatch，注册 systemd
# 按脚本提示安装 PostgreSQL（原生 yum 或单容器）、放置 VictoriaMetrics 二进制
# 编辑 /etc/systemd/system/netwatch-server.service 中的注册令牌与基地址
systemctl enable --now netwatch-server

# 3. 浏览器打开 http://<中心IP>:8080 → 初始化向导
#    建管理员 → 填 SMTP → 录线路（CSV）→ 到"探针管理"绑定探针
#    大屏：http://<中心IP>:8080/#/screen（公开只读，值班室投屏）
```

**备选方案 B（Docker Compose）**：`cd deploy && docker compose up -d`（含 VictoriaMetrics + PostgreSQL + server）。

**探针部署（每楼层 1 台精简 VM，网卡接入本楼层子网）**：

```bash
deploy/install-agent.sh http://<中心IP>:8080 <注册令牌> bin/netwatch-agent
```

## 代码结构

```
cmd/agent/            探针入口（单二进制，部署在楼层子网 VM）
cmd/server/           中心端入口（原生 systemd 或 Docker Compose 部署）
cmd/loadgen/          压测/数据回放工具（仅测试环境，支持身份持久化复用）
web/                  管理后台前端（Vue3 + Bootstrap5 + Chart.js，Uptime Kuma 同栈）
internal/proto/       探针↔中心线上协议（共享）
internal/agent/       探测器（ICMP/TCP/DNS/HTTP、源 IP 绑定、断网缓存补传、配置热更新、自更新）
internal/server/      中心端（探针接入、VictoriaMetrics 写入、告警引擎、测速调度、报表、SMTP、管理 API）
deploy/               部署物（原生 systemd、install-server.sh、探针安装/批量安装脚本、Docker Compose 备选）
docs/                 设计文档、调研报告、开发计划、运维手册、演练与验收、用户手册
```
