## 一句话方案

自研 Go 探针（每楼层子网 1 台精简 VM，出站流量经策略路由天然走本楼层宽带）→ 中心端（Go 服务 + VictoriaMetrics + PostgreSQL，原生 systemd 或 Docker Compose 一键部署）→ Vue3 管理端（复用 Uptime Kuma MIT 组件与设计）+ 大屏 + 邮件/钉钉/企微告警；测速由探针直接对互联网进行（Ookla 协议实现 + HTTP 下载兜底，全局串行错峰）。

## 快速开始（中心端）

```bash
make build                                    # 构建后端二进制 + 前端 web/dist
deploy/install-server.sh                      # 一键部署到 /opt/netwatch 并注册 systemd（幂等）
# 浏览器打开 http://<中心IP>:8080 → 初始化向导（建管理员 → SMTP → 线路 CSV）
# 大屏：http://<中心IP>:8080/#/screen（公开只读，值班室投屏）
```

**探针（每楼层 1 台精简 VM）**：`deploy/install-agent.sh <中心地址> <注册令牌> "" "探针名称"`；批量用 `deploy/batch-install-probes.sh`。详见《docs/部署手册.md》。

## 代码结构

```
cmd/agent/            探针入口（单二进制，部署在楼层子网 VM）
cmd/server/           中心端入口（原生 systemd 或 Docker Compose 部署）
cmd/loadgen/          压测/数据回放工具（仅测试环境）
web/                  管理后台前端（Vue3 + Bootstrap5 + Chart.js，Uptime Kuma 同栈）
internal/proto/       探针↔中心线上协议（共享）
internal/agent/       探测器（ICMP/TCP/DNS/HTTP、源 IP 绑定、断网缓存补传、自更新、资产/出口 IP 自检）
internal/server/      中心端（探针接入、VM 写入、告警引擎、测速调度、报表、通知、管理 API）
deploy/               部署物（install-server.sh、探针安装/批量脚本、systemd、Docker Compose）
docs/                 部署手册 + 数据库表说明（其余知识在 AGENTS.md）
```
